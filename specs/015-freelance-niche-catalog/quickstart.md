# Quickstart: Freelance Niche Catalog Governance

## Prerequisites

- Docker/PostgreSQL local stack available as in the existing `apps/web` MVP.
- `apps/web/.env.local` configured with the local `DATABASE_URL`.
- Existing `014` Freelance web app has been bootstrapped at least once.

## Bootstrap

```bash
cd apps/web
npm install
npm run db:bootstrap
```

## Run Validation

```bash
cd apps/web
npm run typecheck
npm run test
npm run build
```

## Manual Review Flow

1. Start the app:

   ```bash
   cd apps/web
   npm run dev
   ```

2. Open `http://localhost:3000`.

3. Navigate to `Settings -> Niche audit` at `http://localhost:3000/settings/niches`.

4. Run/open the catalog audit. The internal API route is `GET /api/freelance/niche-audit`; passing
   `?fresh=true` persists a new audit run.

5. Confirm:

   - all approved baseline entries are present or reported
   - raw mojibake source names are not shown as final operator-facing names
   - entries include source evidence and conversion hints
   - `Imobiliaria` mismatch keeps both values visible until the operator chooses the approved value
   - screenshot/reference candidates are proposed, deferred, approved, or rejected explicitly as niche catalog candidates
   - no real lead/opportunity is created from a screenshot/reference candidate

6. Open the `Approved niches` tab and create or edit a niche with source evidence, aliases/query terms,
   conversion hint source, enabled state, and sort order.

7. Open the `Candidate review` tab. Confirm reference/image-derived records such as `Imobiliaria`,
   `Clinica de Estetica`, and `Cleaning Service` show source evidence, proposed query terms, and a
   suggested approved-niche match when already covered.

8. Mark one candidate already covered, defer or reject one with a reason, and approve only a genuinely
   new candidate into the governed catalog. These actions must update `niche_candidates` and, on
   approval only, create an approved `freelance_niches` row through the same duplicate/source checks
   used by manual niche creation.

9. Disable one niche and verify it disappears from new campaign creation.

10. Open an old campaign using that niche and verify `nicheNameSnapshot` and `conversionHintSnapshot` still render.

11. Merge a duplicate niche into an enabled approved target and verify it is hidden from new campaign creation.

12. Add or verify the operator-provided `Igrejas` niche with source evidence, then confirm real leads for it still require a scraper/API prospecting flow.

## Out of Scope Checks

- No CSV import/export controls are added.
- No provider-real Maps scraping work is added.
- No automatic outreach send behavior is added.
- No Full-time/job/resume/candidature labels appear in the Freelance catalog UI.
